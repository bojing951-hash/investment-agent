## §一 P2 范围定义

**深研定义**: 多轮竞争性假设深化的研究模式——给定研究问题 → 建立 ≥2 个竞争假设 [实取·注入合同 AC-02§4 条款,2026-11-02 冻结,注入摘要] → 经**快照+门禁**逐轮收集区分性证据 → 证据矩阵赋权 → 判别或按终止条件收束 → 可反驳结论入状态保护并持续跟踪。深研是模式A(自主研究)与模式B(用户自然语言研究)两模式 [实取·注入摘要战略定义(2026-11-02 深夜),非工作树实读]共享的**深化层**,不是另立的独立研究模式。

**是(in-scope)**:
- 深研任务模型(发起/生命周期/档案衔接,§二);
- 证据与数据契约(数据需求分类 ≥4 类+每类三态之一标注 [实取·注入合同 AC-02§3 要求,2026-11-02,注入摘要],§三);
- 假设与论证结构(竞争假设 ≥2+证据矩阵+反方证据强制+多轮深化 [实取·注入合同 AC-02§4 要求,2026-11-02,注入摘要],§四);
- GLM 综合接口的**能力级**衔接(§五);
- 可反驳性与跟踪(falsifiable_conditions 字段级规则+Gate B 对接+结论状态机,§六);
- 实现包拆解(§七)与红线治理(§八)。

**不是(out-of-scope)**:
- **P3 长期积累不属于 P2**(跨年度结论库衰减治理、知识沉淀、长周期档案编研等归 P3,未设计 [注入摘要(2026-11-02 深夜),非工作树实读]);P2 单任务生命周期以轮次预算为界(§二 DP-1),不承诺跨年自动积累;
- **不是交易/仓位/收益类功能**: 战略冻结 = 禁交易、禁管理真实仓位、禁承诺收益 [注入摘要(2026-11-02 深夜),非工作树实读]——本设计任何节不出现交易信号、仓位管理、收益承诺功能;
- 不是绕开快照的取数通道(§八红线1);不是 GLM 替代事实引擎(§五定位);
- 不含 E2E-A/E2E-B/R019 的实现(分别为停泊/设计定稿/在途,INVENTORY 面(b)(d))。

### 2.2 任务生命周期(状态机,append-only)

```
DRAFT ──登记(问题+初始假设集≥2+判别计划)──► ACTIVE(R1..Rn 轮次) ──► TERMINAL ──► TRACKING ──► ARCHIVED
```

- **DRAFT**: 登记研究问题、≥2 个初始竞争假设 [实取·注入合同 AC-02§4,2026-11-02,注入摘要]、每对假设 ≥1 个区分性判据 [示意·非实取,设计提案]、falsifiable_conditions(§六规则推导)、轮次预算(DP-1 登记值);
- **ACTIVE**: 每轮 = 证据收集(快照绑定,§三)→ 证据矩阵更新(§四)→ 假设支持度/反证状态更新 → 轮次记录追加(append-only,轮次不可改写;修订=新版本记录+修订原因,对齐快照 `_v2` 纪律 `scripts/snapshot_builder.py` L390-398 [实取·INVENTORY 面(a.1),2026-11-02]);
- **TERMINAL**(终态 4 种 [示意·非实取,设计提案],§四终止条件触发): `RESOLVED`(区分性判据判定成立,单一假设存续或排序确立)/ `ALL_FALSIFIED`(全部假设被证伪)/ `INCONCLUSIVE`(预算耗尽且无新增证据,或数据阻断)/ `SUPERSEDED`(被新版本深研任务替代);
- **TRACKING**: 结论携 falsifiable_conditions 转持续跟踪(观察记录驱动裁决,复用每日观察先例 `scripts/daily_prediction_observer.py` L124 [实取·INVENTORY 面(a.5),2026-11-02]);
- **ARCHIVED**: 终局归档,记录不可删改。

### 2.3 与 P0-3 研究档案的共享衔接

- 深研任务/假设记录入**共享研究档案**(集合族 `research_tasks` / `anomaly_events` / `query_history`,沿 E2E-B DESIGN §4.1 设计: 档案载体实现由 E2E-B WP-B4 落地,本设计只固定引用约定);
- 一切记录必携 `snapshot_id` + `digest_snapshot` 内容级绑定(R1/R5 机制,INVENTORY 面(a.1));跨模式互操作键 = `metric_id`+`snapshot_id`(E2E-B DESIGN §四同款);
- ID 族决策见 DP-3(待 E2E-A 冻结合同与 R019 定稿后联合对齐,能力级,不在此冻结)。

## §四 假设与论证结构

### 4.1 竞争假设强制(≥2 [实取·注入合同 AC-02§4,2026-11-02,注入摘要])

- 每个深研任务登记 ≥2 个**相互竞争**的假设(能对同一研究问题给出不同机制解释,且存在可区分两者的判据);单假设任务不予立项(DRAFT 登记校验拒收);
- 每对假设登记 ≥1 个**区分性判据**(discriminating evidence): 若判据 E 为真则至多一个假设存活 [示意·非实取,设计提案,DP-6];
- 沿用并深化既有竞争性解释纪律(≥2 竞争假设+区分性判据,能力级衔接 GLM 结论层——**待其定稿,实现包阶段对齐**,§五)。

### 4.2 证据矩阵(假设 × 证据 × 方向 × 权重)

```
EvidenceMatrix = {
  hypotheses: [HypothesisRecord]      # ≥2 条(合同底线 [实取·注入合同 AC-02§4,2026-11-02,注入摘要]);字段含 statement/mechanism_story/状态
  evidence:   [EvidenceRecord]        # §3.3 契约
  cells:      假设×证据 → {direction: 支持|反对|中性, weight: 1-5(DP-2)}
  summary:    每假设 → {支持数(去重: 同一底层指标多次引用计 1 项 [实取·report_generator.py L520 规则登记,2026-11-02]),
                         反证数, 未解释重大反证: bool,
                         机制覆盖数(门槛参照星级规则 3★=2 类/4★=3 类 [实取·report_generator.py L521,2026-11-02])}
}
```

赋权规则复用证据分级 v2 纪律(同源不重复计数/未解释反证封顶 [实取·`scripts/report_generator.py` L520-521,2026-11-02]);矩阵由程序从证据记录确定性汇总,模型不直接改写矩阵数值。

### 4.3 反方证据强制

- 每假设**每轮必须执行反证检索义务**: 对该假设的机制族预测方向,主动检索反向证据并登记;**零反证登记 = 偏差**,任务记录须显式声明「未发现反证+已检索面清单」;
- 反证不计入支持数量,但参与封顶(存在未解释重大反证→该假设确信度封顶,沿 L521 同款纪律 [实取·INVENTORY 面(a.5),2026-11-02]);
- 机制上以「该假设为真则 X 不应发生」的反向预测作为反证检索锚(可反驳性推导,§六)。

### 4.4 多轮深化机制(轮次推进条件与终止条件)

- **推进条件**(满足任一进入下一轮): ①新增可评估证据 ≥1 条 [示意·非实取,设计提案] ②某区分性判据在本轮窗口内可计算 ③反证检索义务未闭合;
- **终止条件**(满足任一收束): ①区分性判据判定成立→`RESOLVED` ②全部假设被证伪→`ALL_FALSIFIED` ③轮次预算耗尽(DP-1)且连续无新增证据→`INCONCLUSIVE` ④数据阻断(快照 Gate A 连续 FAIL 或关键源 MISSING 跨轮)→`INCONCLUSIVE`+阻断登记(如实,不编造);
- 每轮记录 append-only;轮次结论不得回改历史轮记录。

## §六 可反驳性与跟踪

### 6.1 falsifiable_conditions 字段级推导规则(从假设陈述到可机器评估条件)

每假设 ≥1 条 [示意·非实取,设计提案] falsifiable_condition,字段级推导(条件字段 5 项 [示意·非实取,设计提案],扩展自既有预测规格字段 [实取·`scripts/report_generator.py` L525-526,2026-11-02]):

```
FalsifiableCondition = {
  metric_id:    string    # 注册表身份(经 fact_engine.metric() 可解析,INVENTORY 面(c.1))
  operator:     ">=" | "<=" | ">" | "<"    # 比较符(沿既有预测规格 pred_op 词表 [实取·report_generator.py L526,2026-11-02])
  threshold:    number    # 阈值;来源档 3 档 [示意·非实取,设计提案]: 注册表 validation 区间 / 历史分布分位 / 用户显式给定(登记型,先登记后运行禁回改)
  window:       {mode: "expiry"|"touch", deadline或期限}   # 沿 pred_mode/pred_weeks 先例 [实取·同上 L525-526]
  premise:      条件前提(可选)  # 沿 pred_premise_* 先例(前提兑现才开始观察期)[实取·同上 L526]
}
```

推导规则(假设陈述→条件): ①假设陈述中的机制方向映射到可观测指标(注册表身份,缺席→该条件标 `ABSENT_REGISTRY`,沿 E2E-B 缺席路径语义 4 级 [实取·E2E-B DESIGN §三(c) 层级登记,2026-11-02],不以相近指标冒充)②阈值按 §6.1 threshold 来源档登记并记录出处 ③窗口与假设期限一致 ④条件方向 = 「该假设为真则应观察到」(支持向)与「该假设为真则 X 不应发生」(反证向,§4.3);条件一经登记进入观察,**禁回改**(修订=新条件记录+修订原因,append-only)。

### 6.2 评估与 Gate B 对接

- 条件触发核验 = **程序判定**(观察记录驱动,复用每日观察先例 `scripts/daily_prediction_observer.py` L124;终态不参与观察 [实取·INVENTORY 面(a.5),2026-11-02]);
- 深研结论影响论点/观点/预测时,回写必须经 Gate B 状态保护门禁(终态门禁/评级门禁/确信度门禁,`scripts/report_generator.py` L503-505/L522;**Gate B FAIL→禁止一切长期状态回写** `scripts/data_validator.py` L374 [实取·INVENTORY 面(a.4)(a.5),2026-11-02]);
- 深研报告数值经报告校验(`validate_generated_report`)与前置核验(`verify_research_inputs`,核验项 4 件 [实取·INVENTORY 面(a.4),2026-11-02])同款纪律。

### 6.3 结论状态机(含被证伪后的处置路径)

```
未裁决 ──► 部分支持/部分证伪(轮次中)──► 终态:
  CONFIRMED(窗口内支持向条件成立且无未解释重大反证)
  FALSIFIED(证伪向条件触发)──► 证伪后处置(下)
  EXPIRED_UNRESOLVED(窗口结束未触发)
  INCONCLUSIVE(数据阻断)
```

**被证伪后的处置路径**(处置条目 3 条 [示意·非实取,设计提案]):
1. 假设标记 `FALSIFIED`,记录不可改写;实质新假设 = 新假设记录+新 ID(关联引用原假设,沿「不得改写原论点历史结论」同款纪律 [实取·`scripts/report_generator.py` L504,2026-11-02]);
2. 关联论点/观点触发复核: 走终态门禁正向流程(触发器被引擎核验或 ≥2 项新增独立证据 [实取·同上 L503]),由门禁裁决是否进入「已失效」等终态——深研层不直接改写状态;
3. 跟踪任务处置: 原 TRACKING 终止;若反证本身构成新研究问题 → 经 S-3 跟踪触发发起新深研任务(闭环)。

## §八 红线与治理

1. **快照+门禁强制**: 深研一切取数经 select_snapshot+gate_allows_formal_research;禁直读 `data/daily/`;证据无 provenance 不入矩阵(fail-closed);Gate A=FAIL 快照不作正式证据源(§3.1)。
2. **LIVE 禁写**: 全部工作包产物落 DEV 仓与测试沙箱;LIVE 路径与 launchd 零触碰(本设计包零写入已取证)。
3. **禁交易/仓位/收益承诺**: 战略冻结重申(§一);深研结论表述纪律 = **研究结论禁止构成投资建议**——报告措辞沿既有先例(评分卡「内部模型观点非客观事实」免责声明 `scripts/macro_scorecard.py` L32-33 [实取·本文件,2026-11-02]);不产出任何交易信号/仓位建议/收益承诺。
4. **append-only 不可改写**: 任务/假设/条件/轮次记录只追加;登记型参数先登记后运行禁回改(DP-1/2/6,写入验收要点);修订=新版本+原因留档。
5. **GLM/凭证/费用类动作确认权留用户**(DP-4/DP-5);本设计包零 GLM 调用、零凭证触碰、零付费(零 API 痕迹)。
6. **如实纪律**: 数据缺席走结构化 NO_DATA 不编造;阻断如实标登记;禁以相近指标冒充/内插/填 0(与引擎「不填 0」实现同源,E3/M1/C5 共 3 处 [实取·E2E-B DESIGN §三(c)/§七4 同源登记,2026-11-02];INVENTORY 面(c.1))。
