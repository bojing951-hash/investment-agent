## §1 P3 范围定义

**P3 定位**: 第四层收尾层——长期积累与成果整合。P0~P2 建成"单期研究闭环"(事实→快照→门禁→报告→状态保护→深研),P3 解决**跨期**: 已产出研究成果(档案/论点/观点/预测/报告)的检索、版本化、修正、关联、跟踪、复盘、质量优化,并与用户个人研究流程整合,最终以项目总封版收尾。

**是(in-scope)**(范围权威 #31-38 [实取·注入摘要·handover §4a 第四层逐字块(2026-11-03),非工作树实读],逐项映射见下表):

- **P0-3/P1/P2 已定范围不重做不重设计**: E2E-A/B 模式实现、GLM 研究结论层实现、四经济体数据扩展、深研任务模型实现——P3 只做**能力级衔接标记**(实现停泊面,INVENTORY 面(d));

## §3 知识与档案检索 + 版本管理(#31/#32)

### 3.1 快照纪律(红线,先于一切检索/索引/关联设计)

- 检索索引的**构建输入** = 门禁后的正式产物: 不可变快照(Gate A 经 `gate_allows_formal_research` 放行口径,`scripts/research_provenance.py` L1183 [实取·INVENTORY a.3,2026-11-03])、经 Gate B 发布的正式周报(L909-924 发布事务 [实取·INVENTORY a.4,2026-11-03])、门禁后状态文件(thesis/allocation_views);
- **禁止直读原始文件**: 索引器/关联扫描器/复盘统计器一律不得直接读取 `data/daily/` 采集件(与 L4"研究引擎全部改吃快照"同源纪律 [实取·`docs/ARCHITECTURE_V2.md` L42-46,2026-11-03]);
- 索引 = **衍生物**: 随时可从权威源确定性重建;索引损坏/漂移 → 重建,不得反向修改任何权威档;查询结果引用一律落到源档档键(snapshot_id+digest / 报告档键 / 状态记录键),不复制数值语义为第二事实源。

### 3.2 检索面设计(#31;检索对象 × 维度 × 查询形态)

**检索对象**(第一期 4 类,第二期 +1 类 [实取·本节枚举,2026-11-03]): ①快照事实(经 select_snapshot 版本选择)②正式报告(周/月/季,按发布状态认定正式性,`scripts/research_provenance.py` L1493/L1505 [实取·INVENTORY a.3,2026-11-03])③论点/观点/预测状态记录 ④结论版本记录(§3.3 新增,随建随入索引)⑤深研任务档案(O-5,接口预留)。

**检索维度**(登记型字段集,字段 6 项 [实取·本节枚举,2026-11-03]): metric_id / 时间窗(obs_date 区间)/ 资产 / 机制类别(词表沿用证据分级 mechanism 7 类 [实取·`scripts/report_generator.py` L518,2026-11-03])/ 结论状态(论点 4 值 + 预测 4 值词表 [实取·同文件 L501/L534,2026-11-03])/ 档键前缀(QB-/RT-/VER- 等族)。

**查询形态**(3 种 [实取·本节枚举,2026-11-03]):
- (a) **结构化查询**: 程序 API(离线纯函数,零网络零 GLM),输入=维度过滤器,输出=档键引用列表(非数值本身);
- (b) **自然语言查询**: 复用模式B NL→IR 映射(E2E-B 设计定稿,实现停泊——能力级衔接 [实取·INVENTORY b.1,2026-11-03]),IR 落到 (a) 执行;
- (c) **关联扫描**: 批处理事件驱动(§4.1 触发),非用户发起。

**索引形态决策**: 见 DP-1(旁路索引文件,事件触发增量更新,登记型先登记后运行)。

### 3.3 版本管理与历史结论修正机制(#32)

**结论版本链**(新增旁路记录族,append-only):
- 版本记录 = {版本键(VER-YYYYMMDD-NNN 族)/对象类型(论点|观点|预测|深研结论)/对象 ID/变更类型/变更前值/变更后值/门禁依据(触发器 ID 或 ≥2 项程序验证证据引用)/快照引用(snapshot_id+digest)/时间戳};字段 9 项 [示意·非实取,设计提案];
- **写入时机**: 挂接既有回写路径(状态变更被门禁放行时同步生成版本记录)——不改动既有回写签名,以旁路写入实现;history 散记数组保留为展示层,不迁移不改写(`config/thesis.json` L28-33 现状 [实取·INVENTORY c.2,2026-11-03]);
- **修正机制**: 历史结论修正 = 修正提案 → **与现行状态变更完全相同的门禁**(终态门禁/评级门禁/确信度门禁,`scripts/report_generator.py` L503/L505/L522 [实取·INVENTORY a.1,2026-11-03])→ 版本链追加;**不设任何弱门禁旁路**;实质新假设=新对象+新 ID 关联引用原对象(沿 L504"不得改写原论点历史结论"纪律 [实取·同上]);
- **结论状态机**: 承接 P2 §六定稿设计(2.3 衔接声明;`docs/P2_DESIGN.md` L172-185 [实取·INVENTORY b.2,2026-11-03]): 跨期结论沿 未裁决→部分支持/部分证伪→终态(CONFIRMED/FALSIFIED/EXPIRED_UNRESOLVED/INCONCLUSIVE)流转;证伪后处置 3 条(标记不可改写/关联论点走门禁复核/反证构成新研究问题经 S-3 闭环)原文承接;
- **快照级版本管理在场且沿用**(research_snapshot _v2/revision_reason/确定性版本选择,INVENTORY a.5),本节版本链为**研究结论级**,两层互不替代。

## §4 关联与持续跟踪(#33/#34)

### 4.1 新证据↔旧观点自动关联(#33;触发/匹配/呈现三要素)

**触发**(事件驱动,3 类 [实取·本节枚举,2026-11-03]): ①新快照经 Gate A 放行落档后 ②预测裁决落档(终态变更时)③新正式周报发布后。触发器消费门禁后事件流,**不轮询原始数据**。

**匹配**(分层,层 3 层 [实取·本节枚举,2026-11-03]):
- 第一层 精确匹配: metric_id 同指标命中旧观点/论点的 quant_triggers 与 invalidation 规格(复用既有结构 `config/thesis.json` L34-60 / `config/allocation_views.json` L38-49 [实取·INVENTORY a.1,2026-11-03]),零 GLM;
- 第二层 规则匹配: 机制类别+资产标签交叉(词表沿用 L518 mechanism 7 类 [实取·`scripts/report_generator.py` L518,2026-11-03]),零 GLM;
- 第三层 语义匹配(可选扩展,**PENDING·确认权留用户**): 需真实 GLM 调用,启用前另拟含真实调用的工作包并显式 PENDING·用户实批前置(DP-4);第一/二层为零 GLM 路径。

**呈现**: 关联报告条目 = {关联对(新证据档键 ↔ 旧观点对象 ID)/匹配层/证据引用(含 snapshot_id+digest)/建议动作(复核|提案|忽略)};字段 4 项 [示意·非实取,设计提案]。**关联不直接改任何状态**——建议动作中的"提案"仅生成提案,须走既有门禁(a.1)裁决;关联记录本身 append-only 入关联档案(旁路件,可重建)。

### 4.2 论点与资产观点持续跟踪(#34)

- **沿用既有状态保护,不绕开**: 论点/观点状态变更一律经 Gate B 状态保护(终态门禁/终态退出门禁/评级变更门禁/确信度门禁,`scripts/report_generator.py` L503-504/L505/L522 [实取·INVENTORY a.1,2026-11-03]);Gate B FAIL → 禁止一切长期状态回写(`scripts/data_validator.py` L374 [实取·INVENTORY a.5,2026-11-03]);
- P3 增量 = 跟踪的**提醒与聚合面**: 未决触发器跨期清单(❓待验证/⏳持续确认中项按对象聚合,词表 `scripts/allocation_engine.py` L1052-1053 [实取·INVENTORY a.1,2026-11-03])、到期预测裁决待办(⏰已到期口径 L1070 [实取·同上])——两者均为**只读聚合视图**,数据源为状态文件,呈现载体为周报既有槽位或旁路简报,不改回写路径;
- 跟踪触发的"触发后再研究"入口 = P2 S-3 设计定稿(实现停泊,能力级衔接 [实取·INVENTORY a.6/P2_DESIGN L41,2026-11-03]),P3 不重复实现。

### 5.2 错误模式复盘方法论(模式归类 / 统计口径 / 反馈闭环)

## §8 红线与治理

1. **快照+门禁强制**: 检索索引构建/关联扫描/复盘统计/质量循环一切取数,输入限门禁后正式产物(§3.1);禁直读 `data/daily/`;Gate A FAIL 快照不作检索源;Gate B FAIL 禁止一切长期状态回写(`scripts/data_validator.py` L374 [实取·INVENTORY a.5,2026-11-03])。
2. **LIVE 禁写**: 全部工作包产物落 DEV 仓与测试沙箱;LIVE 路径与 launchd 零触碰(用户保留卡点 [实取·注入摘要(2026-11-03),非工作树实读])。
3. **禁投资建议表述**: 研究结论禁止构成投资建议;评级≠仓位指令(`scripts/allocation_engine.py` L1040 在场先例 [实取·INVENTORY a.1 引用区,2026-11-03]);免责表述沿 `scripts/macro_scorecard.py` L32-33 先例;零交易信号/仓位建议/收益承诺。
4. **长期状态批量修改须用户批准**(治理不变量,P3 高频触碰面,显式红线): 论点/观点/预测长期状态的**批量**修改无程序通道,须用户批准;单条变更仍走既有门禁;P3 各新增件(版本链/关联档案/统计)为旁路 append-only 记录,批量修改红线同样适用 [实取·注入摘要(2026-11-03),非工作树实读]。
5. **append-only 禁回改**: 版本记录/关联记录/标注档/终验清单只追加;登记型参数(DP-1/2/3/5/6/7 与各包登记项)先登记后运行禁回改,已写入各包验收要点(承接 R020-D5 [实取·注入摘要(2026-11-03),非工作树实读])。
6. **GLM/凭证/费用类动作确认权留用户**(DP-4/DP-8/DP-9/WP-P3-E/F PENDING);本设计包零 GLM 调用、零凭证、零付费、零网络出站。
7. **如实纪律**: 统计缺席走结构化 NO_DATA;阻断如实标登记;禁以相近指标冒充/填 0(与引擎"不回退 0.0"同源,`scripts/fact_engine.py` L90 [实取·INVENTORY c.1,2026-11-03])。
