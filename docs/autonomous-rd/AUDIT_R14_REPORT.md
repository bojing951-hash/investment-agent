## 二、根因与修复(scripts/research_orchestrator.py,共享解析逻辑,零例句特判)

### 根因

①**连接词不完整**: `_QCONT_RE` 连接词类只有 `[零又加+]`——「加上」「再加」形逃逸(「十八个月**加上**三天」的 加 后 上 不属数量词,整体不命中=按十八个月放行)。②**单位类缺口**: 「个」前缀只给了月——「零**一个**星期」的一 后 个 不属单位;「交易**日**」不在单位类——「零三个**交易日**」的 个 后 交 不属单位,两形均逃逸。③**half 组吞行业名**: `半(?!年)` 词界只防「半年度」——「三年**半导体**」的 半 后随 导(非年),half 组消费=误折 42 月;加「的」后 half 不命中=3 年,两形不同窗。④**期限词形误作复合尾部**: 「7天**期**」的 天 无期护栏——`六个月7天期` 的 7+天 命中复合尾部=unparseable(时间解析错误),而它是指标期限(N 天期逆回购),应保持六月窗+缺数如实。

### 修复位置

| 文件:函数 | 修改 |
| --- | --- |
| `research_orchestrator.py`:`_QCONT_RE` | **连接词扩容**——`(?:(?:再\s*)?加上?\|[零又加+])`(再加上/加上/再加形);**单位侧三扩**——①「个」前缀推广到 星期/季度/交易日/日(零一个星期);②「交易日」单位(零三个交易日);③**期限后缀护栏** 天/月 不带「期」(7天期/1个月期=指标期限词形,不作复合时长) |
| 同上:`_QRANGE_RE` half 组 | **后随白名单**——`半(?!年)(?=[^一-鿿]\|的之以之到至内来左右和与及跟零又加时\|$)`:「半」是 N年半 后缀仅当其后为非汉字(空白/ASCII/标点/句尾)或后续虚词/连接词;后随其它汉字=「半」开头的行业/术语词形(半导体/半衰期),归行业名不归 half——「过去三年半导体需求」=三年窗;「一年半零三天」(半 后 零)仍 BAD;「三年半年度」(期)仍让位术语判定 |
| 同上:`_QNUM_RESIDUAL_RE` | 月护栏同步 `月(?!份\|期)`——期限词形在残缺扫描器同口径豁免(六个月1个月期 不再被残缺扫描误拒) |
| 同上(既有结构确认) | plan、报告和归档**同一份窗口判定**——三阶段全走 run_research→_question_window→_evaluate_data_requirements 单源(S1 实体映射/需求判定 item 唯一);本轮零新增入口,以 §G 正式 plan+report/archive 双门验证同源 |
