## 三、P0：修复自主研发系统的状态管理

最新独立审计发现：

项目实际已经执行至R19，但 CURRENT_STATE.md 顶部仍保留R15快照，RESUME.md 仍包含已经完成的任务。

这意味着上下文丢失后，AI可能根据过期状态重复开发。

必须彻底解决。

### 3.1 建立唯一权威状态

重新设计现有状态管理方式。

要求：

1. 当前研发状态只能有一个权威入口。
2. 历史研发记录与当前状态严格分离。
3. 已完成任务不能重新出现在当前待办中。
4. 每个任务具有唯一ID、状态和Git证据。
5. 当前状态必须与实际仓库一致。
6. 恢复时必须核对最新Git HEAD，而不是盲目信任文档。

允许复用现有文件，不要求增加新文件数量。

### 3.2 建立自动状态更新

每轮研发结束后，自动完成：

读取实际Git状态 → 检查本轮任务结果 → 更新能力矩阵 → 更新未解决问题 → 追加研发日志 → 更新当前状态 → 生成恢复检查点 → 验证检查点一致性 → 进入下一轮

必须建立自动一致性检查。

如果状态文件存在矛盾，禁止直接进入开发，应先恢复正确状态。

### 3.3 上下文恢复验收

执行真实恢复测试：

* 模拟上下文丢失。
* 从项目文件恢复任务。
* 核对实际Git HEAD。
* 检查是否重复执行已完成任务。
* 检查是否丢失未完成任务。
* 检查最终目标是否完整保留。

成功标准：一个完全没有此前聊天上下文的新Agent，能够准确恢复当前研发状态并继续工作。

## 四、P0：验证并完善自主持续执行

检查当前实际使用的：

* Claude Code上下文压缩机制。
* PreCompact Hook。
* SessionStart Hook。
* Stop Hook或其他持续执行机制。
* 本地 ~/agent-loop/。
* macOS launchd定时任务。
* 自动重启与恢复机制。
* 资源和权限限制。

不得根据历史文档声称已经配置成功。

必须检查真实配置、运行日志和执行结果。

### 4.1 自动上下文管理

要求：

上下文正常时：持续研发。

上下文接近限制时：保存Checkpoint，使用受支持的压缩机制。

上下文压缩后：重新读取项目状态，核对Git，继续当前任务。

会话中断后：在实际支持的执行环境中自动恢复。

进程退出后：由经过验证的外部监督机制重新启动，前提是已有相应授权。

不能依赖聊天记录保存关键研发状态。

### 4.2 自主研发循环

每轮执行：

AUDIT → PRIORITIZE → DESIGN → IMPLEMENT → TEST → INDEPENDENT REVIEW → CHECKPOINT → FINAL GOAL CHECK → 未完成 → NEXT ITERATION

不需要用户每轮发送"继续"。

### 4.3 防止死循环

必须能够识别：

* 重复修复同一个问题。
* 连续多轮没有实质进展。
* 重复运行相同测试。
* 研发目标漂移。
* 为通过测试而降低验收标准。
* 只修改文档而没有改善实际能力。

连续两轮没有实质进展时，必须重新审查根因和技术方案。

不能为了保持运行而无意义地消耗资源。

### 4.4 执行环境验收

必须实际测试：

1. 一轮完成后自动进入下一轮。
2. 上下文压缩后恢复。
3. 新会话从检查点恢复。
4. 任务失败后安全重试。
5. 资源限制触发后正确停止。
6. 无法获得授权时正确停止。
7. 外部监督程序能够在授权范围内恢复中断任务。

如果某项能力当前环境不支持，明确标记NOT_VERIFIED或FAIL，不得假装成功。

## 五、P0：修复金融研究正确性

上一轮独立审计发现以下问题。

首先复现，确认后修复。

### 5.1 汇率报价方向

当前存在：

日元 → USDJPY

但"日元升值"不等于USDJPY上涨。

必须建立金融指标方向语义规则。

例如：

USDJPY从150下降至145，代表日元相对美元升值。

不能将该预测机械判为错误。

扩展测试覆盖：

* USDJPY。
* EURUSD。
* 美元指数。
* 利率。
* 国债价格与收益率。
* 其他存在反向报价或反向经济含义的指标。

### 5.2 预测到期数据新鲜度

当前到期验证可能使用距离预测到期日很远的历史观测。

必须增加：

* 预测到期日。
* 实际观测日期。
* 数据发布日期。
* 允许的数据滞后。
* 数据质量状态。

如果没有足够接近预测到期日的有效数据，不得输出预测正确或错误。

必须返回证据不足。

### 5.3 观点标签与证据绑定

检查 view_plausibility.py。

不能仅仅验证：

* 标签属于合法枚举。
* 引用索引合法。
* 聚合结果一致。

必须验证：

标签是否真正由对应证据产生。

对于机器可验证的证据，重新计算判定。

对于需要经济学解释的证据，明确标记AI推断和人工审查边界。

不得允许底层证据为NOT_YET_TESTABLE，却无充分其他证据就将同一预测标记为SUPPORTED。

### 5.4 历史数据与前视偏差

检查：

* 历史数据修订。
* 数据发布日期。
* 机构观点发布时间。
* 预测期限。
* 观察窗口。
* 统计口径。
* 历史信息集。

无法重建历史真实信息集时，必须明确降级。

不能用今天修订后的数据冒充当时已知信息。

* 识别重要经济矛盾。
* 选择相关指标和机构观点。

* 拆解经济传导机制。

### 6.3 一句话完成研究

最终用户输入：

"生成当前全球宏观研究地图，整合主要机构观点，分析经济传导机制，验证客观证据，并形成独立研究结论。"

### 6.4 完整研究验收

* 当前经济事实。

* 机构观点逻辑链。
* 经济传导机制。
* 历史相似结构。
* 支持与反对证据。
* 独立研究结论。
* 条件情景。
* 证伪标准。

独立审计者必须检查结论是否真正由证据支持。
